# Deep Research Agent 内部设计笔记

> ⚠️ 本文档是 **Deep Research Agent 项目的演示语料**，用于演示"本地知识库检索"能力。
> 其中的参数与数据均为项目自身的真实配置与实测结果，可直接核验。

## 1. 为什么用 LangGraph 而不是手写循环

早期版本用 `while` 循环 + 状态字典手写研究流程，遇到两个问题：

1. **状态合并靠人工维护**。并行分支写回结果时要手动 `extend`，一旦漏了就静默丢数据。
2. **中断恢复无从下手**。想在中途插入人工确认（比如让用户改研究计划）必须改动主循环。

改用 LangGraph 后，状态字段用 `Annotated[list, operator.add]` 声明 reducer，
并行节点写回时自动合并；条件边用函数表达，反思后"继续搜索还是进入写作"变成一行返回值。
主流程因此从约 200 行降到不到 40 行。

## 2. 关键参数与取值理由

| 参数 | 取值 | 理由 |
|---|---|---|
| `MAX_ITERATIONS` | 3 | 实测第 3 轮的新增事实已明显衰减，第 4 轮边际收益接近 0 |
| `MAX_PAGES_PER_ROUND` | 12 | 与 `MAX_CONCURRENCY=5` 搭配，单轮阅读耗时约 50~150 秒 |
| `MAX_PAGE_CHARS` | 6000 | 单页送入 LLM 的上限，超过后只截前 6000 字符，控制 Token |
| `DEDUP_SIMILARITY` | 0.90 | 事实去重阈值；低于 0.85 会误合并不同数据点 |
| `MIN_FACT_CONFIDENCE` | 0.30 | 低于此值的事实直接丢弃 |
| `SEARCH_RESULTS_PER_QUERY` | 5 | 每关键词取 5 条，再多则去重后新增极少 |

## 3. 三个踩过的坑

### 3.1 检索词判重阈值定得太低

`is_repeated()` 最初用 `SequenceMatcher` 相似度阈值 **0.75** 判重。
实测发现"离线自检 补充证据1"与"离线自检 数据1"的相似度**恰好是 0.750**，
导致两个真正不同的补充检索词被当成重复，其中一个被丢弃。

修复：阈值提到 **0.90**，并给包含关系判定加长度保护——
短词必须不短于长词的 **60%** 才算重复，否则"AI"会命中一切检索词。

### 3.2 冲突检测把 URL 里的编号当成数据矛盾

`detect_conflicts()` 最初只要求"文本相似 ≥ 0.55 且数字不同"，
结果把来源 URL 里的 `page-3`、`page-4` 读成了互相矛盾的数据，
一次运行误报 **25 组冲突**。

修复：改成严格判定——**去掉 URL 后、把数字抹掉，两句话必须完全一致**，
只是数字不同才算矛盾。修复后误报降为 0，真实矛盾仍能识别。

### 3.3 xhtml2pdf 静默降级成 Helvetica

xhtml2pdf 0.2.20 起引入资源沙箱，文档只能读取"自己的目录"，
因此 `C:\Windows\Fonts` 下的中文字体被判为越权读取，
PDF 里的中文全部变成方框——**而 PDF 照样生成成功，不报错**。

修复：① 按最小授权原则只把字体目录加进白名单；
② 用 `@font-face` 内嵌字体；③ CSS 加全局字体规则覆盖 `<title>` 等元素；
④ 抓取 xhtml2pdf 日志 + 用 pypdf 抽回 PDF 文本核对中文，把静默降级变成明确失败。

## 5. 已知局限

- **观点型矛盾检测不到**：`detect_conflicts()` 只能发现"同一句话、数字不同"这类数值冲突。
  例如"a16z 称推理成本每年降 10 倍"与"某博客称成本并未下降"这种**不同表述的观点对立**，
  规则层检测不到，目前依赖反思器（LLM）定性捕捉。
- **引用准确率有两个口径**：403/429 属于站点反爬，不代表链接失效，
  因此把"严格可访问"与"链接存在"分开统计。
